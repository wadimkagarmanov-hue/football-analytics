# Футбольная аналитика

Адаптивный аналитический сайт на русском языке: коэффициенты букмекеров, команды, составы и статистика матчей.
**Сайт не принимает ставки** — это только аналитика. На каждой странице: метка «18+», заметка об ответственной игре и фраза
«Сайт не гарантирует результат. Ставки связаны с риском потери денег»; в подвале — контакты организаций помощи при игровой зависимости.

Стек: Next.js 15 (App Router) + TypeScript, Tailwind CSS 3, PostgreSQL, фоновый воркер (`tsx`). Тёмная и светлая темы, mobile-first.

## Быстрый старт (демо-режим, без ключей и без БД)

```bash
npm install
cp .env.example .env      # по умолчанию FOOTBALL_PROVIDER=mock, ODDS_PROVIDER=mock
npm run dev               # http://localhost:3000
```

В демо-режиме данные **вымышленные** (3 лиги, 24 команды, игроки и коэффициенты генерируются детерминированно), об этом
сообщает плашка под шапкой. Проверка слоя данных без Next.js: `npm run selftest`.

## Запуск с PostgreSQL и воркером

```bash
docker compose up -d db                 # Postgres 16 на localhost:5432
# в .env: DATABASE_URL=postgres://football:football@localhost:5432/football
npm run db:migrate                      # применяет db/schema.sql
npm run dev                             # веб
npm run worker                          # фоновые обновления (отдельный процесс)
```

Без `DATABASE_URL` сайт работает: кэш только в памяти, история коэффициентов берётся из провайдера
(у демо-провайдера она есть; у The Odds API её нет — она копится воркером в БД).

Прод-сборка: `npm run build && npm start`; воркер запускайте отдельным процессом (systemd, pm2, отдельный контейнер).

```
src/config/helplines.ts          организации помощи при игровой зависимости (подвал, /responsible)
src/lib/
  types.ts                       доменные типы — единственный язык интерфейса
  providers/types.ts             контракты FootballProvider / OddsProvider
  providers/index.ts             выбор провайдера по переменным окружения
  providers/mock.ts              демо-провайдер
  providers/apifootball.ts       адаптер API-Football
  providers/theoddsapi.ts        адаптер The Odds API
  cache.ts                       кэш с TTL: память → таблица api_cache → провайдер; stale-данные при сбое
  ratelimit.ts                   лимитер запросов (в минуту и в сутки на провайдера)
  data.ts                        сервисный слой: всё, что читают страницы
  analytics.ts                   форма, рекорды, H2H, условия фильтра, средние показатели
  odds.ts                        маржа, вероятности, лучшие цены, группировка рынков
  affiliates.ts                  партнёрские ссылки с учётом региона
src/app/                         страницы и API-маршруты
src/components/                  интерфейс (таблицы с сортировкой, график, составы, калькулятор…)
src/worker/index.ts              фоновый воркер
```

## Структура базы данных

| Таблица | Назначение |
|---|---|
| `leagues`, `teams`, `matches` | зеркало справочников и расписания; заполняет воркер (`id` — идентификаторы текущего провайдера) |
| `odds_snapshots` | история коэффициентов: одна строка = одно изменение цены (`match_id`, `bookmaker`, `market`, `line`, `selection`, `price`, `captured_at`); из неё строится график |
| `api_cache` | общий кэш ответов провайдеров (`key`, `value jsonb`, `fetched_at`) — делится между веб-процессом и воркером |
| `users`, `favorites` | задел под аккаунты. Сейчас избранное хранится в `localStorage`, UI аккаунтов не реализован |

Рынки: `1X2`, `TOTAL` (линия тотала), `BTTS` (обе забьют), `HANDICAP` (линия форы хозяев). Исходы: `1/X/2`, `Over/Under`, `Yes/No`, `Home/Away`.

## Схема интеграции с API

```
Страницы / API-маршруты
        │  используют только доменные типы
        ▼
   lib/data.ts  ──►  cache.ts  ──►  ratelimit.ts  ──►  providers/*
        ▲               │  память → api_cache (БД)         │
        │               └── stale-ответ при ошибке/лимите  ├─ mock
   worker/index.ts ── принудительное обновление ───────────┼─ apifootball (FootballProvider)
        └── пишет odds_snapshots                           └─ theoddsapi  (OddsProvider)
```

- **Смена провайдера без правок интерфейса.** Реализуйте `FootballProvider` или `OddsProvider` (`src/lib/providers/types.ts`),
  верните доменные типы, добавьте ветку в `providers/index.ts` и задайте `FOOTBALL_PROVIDER` / `ODDS_PROVIDER`.
- **Кэш.** TTL по типам данных — `src/lib/config.ts` (коэффициенты 30 с, составы 2 мин, расписание 5 мин, таблицы 10 мин, справочники 24 ч).
  Одинаковые параллельные запросы схлопываются в один.
- **Лимиты.** Перед каждым обращением к провайдеру занимается слот лимитера (`RATE_LIMIT_PER_MIN_<ИМЯ>`, `RATE_LIMIT_PER_DAY_<ИМЯ>`).
  Если слота нет или провайдер ответил ошибкой, отдаётся устаревший кэш с пометкой — в интерфейсе она показана красным.
- **Время обновления** показано на главной, в таблицах лиг и на странице матча («Обновлено ЧЧ:ММ:СС · источник»).
- **Реальное время.** Страница матча каждые `NEXT_PUBLIC_LIVE_POLL_MS` (по умолчанию 30 с) опрашивает `/api/matches/<id>/live`
  и обновляет коэффициенты, график и составы; на скрытой вкладке и для завершённых матчей опрос не идёт.
- **Ключи** хранятся только в переменных окружения и на клиент не попадают.

### Подключение реальных провайдеров

1. `FOOTBALL_PROVIDER=apifootball`, `APIFOOTBALL_KEY=…`, `FOOTBALL_LEAGUE_IDS=39,140,78`, `FOOTBALL_SEASON=2026`.
2. `ODDS_PROVIDER=theoddsapi`, `THEODDSAPI_KEY=…`, `ODDS_SPORT_KEYS` — соответствие id лиги и sport key.
3. Задайте лимиты своего тарифа в `RATE_LIMIT_*`.

> **Адаптеры написаны по документации и не проверялись на живых ключах.** Перед запуском в прод пройдите все страницы
> на вашем тарифе и сверьте поля (особенно: названия команд при сопоставлении матчей с коэффициентами, наличие xG,
> рынок «обе забьют», состав игроков). Условия лицензий провайдеров (отображение, кэширование, хранение истории) проверьте сами.

## Переменные окружения

См. `.env.example` с комментариями. Кратко:

| Переменная | Назначение |
|---|---|
| `NEXT_PUBLIC_DISPLAY_TZ` | часовой пояс отображения (по умолчанию `Europe/Moscow`) |
| `NEXT_PUBLIC_LIVE_POLL_MS` | период опроса страницы матча, мс |
| `OPERATOR_NAME`, `OPERATOR_EMAIL` | данные организации в подвале и политике конфиденциальности |
| `DATABASE_URL` | строка подключения PostgreSQL (необязательна) |
| `FOOTBALL_PROVIDER`, `ODDS_PROVIDER` | `mock` / `apifootball` и `mock` / `theoddsapi` |
| `APIFOOTBALL_KEY`, `APIFOOTBALL_BASE_URL`, `FOOTBALL_LEAGUE_IDS`, `FOOTBALL_SEASON` | API-Football |
| `THEODDSAPI_KEY`, `ODDS_SPORT_KEYS`, `ODDS_REGIONS` | The Odds API |
| `RATE_LIMIT_PER_MIN_<ИМЯ>`, `RATE_LIMIT_PER_DAY_<ИМЯ>` | лимиты запросов (`<ИМЯ>` — `APIFOOTBALL`, `THEODDSAPI`) |
| `WORKER_ODDS_INTERVAL_SEC`, `WORKER_LINEUPS_INTERVAL_SEC`, `WORKER_CORE_INTERVAL_SEC` | периоды воркера |
| `AFFILIATES_JSON` | партнёрские ссылки (см. ниже) |

## Страницы

| Путь | Содержимое |
|---|---|
| `/` | матчи на сегодня и ближайшие дни; фильтры: лига, страна, дата и период, поиск по командам, условие по форме (например, «хозяева не проигрывали дома N матчей»); в таблице лучшие П1/Х/П2, ТБ 2.5, ОЗ |
| `/match/[id]` | коэффициенты 1X2 / тотал / обе забьют / форы с выделением лучшего и маржой; график движения; составы (вероятные/подтверждённые), травмы, дисквалификации; форма 5/10 матчей; личные встречи; дом/выезд; xG, владение, удары, угловые, карточки; калькулятор |
| `/team/[id]` | календарь, результаты, состав, тренер, статистика сезона |
| `/player/[id]` | позиция, статистика, статус (травма/дисквалификация), последние матчи |
| `/leagues`, `/leagues/[id]` | таблица лиги и расписание по турам |
| `/compare?a=&b=` | сравнение двух команд бок о бок |
| `/favorites` | сохранённые матчи и команды (localStorage) |
| `/privacy`, `/responsible` | политика конфиденциальности (шаблон), ответственная игра |

Экспорт CSV (кнопки на страницах): `/api/export?kind=standings|team-matches|squad|odds|match-stats|compare`.

## Требования к юридической части

- **18+, ответственная игра, фраза о риске** — в шапке/под шапкой каждой страницы (`ResponsibleStrip`) и в подвале.
- **Помощь при игровой зависимости** — `src/config/helplines.ts`. Там международные и англоязычные организации: **добавьте службы для региона вашей аудитории** и проверьте актуальность контактов.
- **Cookie** — баннер с выбором (`ConsentBanner`); сейчас используется только необходимое хранилище. Любые аналитические скрипты запускайте только при `consent.analytics === true`.
- **Политика конфиденциальности** — шаблон; согласуйте с юристом под вашу юрисдикцию.
- **Партнёрские ссылки** — `AFFILIATES_JSON`:
  `[{"name":"…","url":"https://…","regions":["RU"],"license":"номер лицензии"}]`.
  Показываются только если страна пользователя (заголовки `cf-ipcountry` / `x-vercel-ip-country` / `x-country-code`) входит в `regions`,
  указана лицензия, и всегда с пометкой «Реклама». Нет страны или лицензии — ссылок нет. Реклама азартных игр регулируется
  законодательством, проверьте допустимость размещения для вашей аудитории.

## Известные ограничения

- Интерфейс аккаунтов не реализован (таблицы `users`/`favorites` — задел).
- Статистика матчей и средние (xG, владение…) считаются по запросам статистики каждого матча: на реальном провайдере это расход лимита
  (кэшируется на 24 ч для сыгранных матчей).
- Даты в фильтре главной интерпретируются в часовом поясе `NEXT_PUBLIC_DISPLAY_TZ`.
